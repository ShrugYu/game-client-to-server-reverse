# 功能清单（Function Checklist）— <游戏名>

> **用途**：把"哪些功能通了、哪些没通"写成一张可维护的表，**反复迭代直到基本完善**。
> 与 `TRACKER.md`（进度/接口）、`docs/status/support-matrix.md`（三轴状态）保持同步。
> **配套**：`references/workflow-roadmap.md` 阶段 4、`references/live-ops.md`。

> **状态图例**：`[x] 已实现` / `[~] 部分` / `[ ] 未做` / `[?] 未验证` / `[-] 游戏本身没有`

> 注意: **三件事分开记**（铁律 5）：**服务端实现了** / **自动测试覆盖了** / **客户端验收了**。
> 只用一列会掩盖后两项。下表用三列区分。
